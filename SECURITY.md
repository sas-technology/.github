# Security Policy

SAS Technology repositories may touch systems or data belonging to
Singapore American School, including student, staff, and family
information. Treat any suspected vulnerability as sensitive by
default.

## Reporting a vulnerability

**Do not open a public issue for a security concern.** Instead:

1. Use GitHub's **[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability)**
   on the affected repository (Security tab → "Report a vulnerability"),
   if it's enabled there, **or**
2. Email **[edtech@sas.edu.sg](mailto:edtech@sas.edu.sg)** with
   a description, affected repo/system, and reproduction steps if you
   have them.

## General IT help

For anything that isn't a security concern (access, accounts, devices,
everyday IT questions), email
**[ithelp@sas.edu.sg](mailto:ithelp@sas.edu.sg)**.

## What to expect

- Acknowledgement within **2 business days**.
- A plan or fix timeline once the report is triaged.
- Credit if you'd like it, once a fix has shipped — otherwise we keep
  reporters confidential by default.

## Scope

This covers every repository in the `sas-technology` GitHub
organization unless that repository ships its own `SECURITY.md`
(which takes precedence for that repo).

## Out of scope

- Social engineering or physical attacks against SAS staff or
  facilities — report those directly to SAS Technology leadership,
  not via GitHub.
- Findings in third-party services we merely use (report upstream).
